# Bevy 代码大规模审查报告

审查范围：`starforge-bevy/src` 全部 Bevy/Rust 模块、系统注册与状态切换、地形流式加载、存档、原生 UDP 联机、实体生命周期，以及现有单元测试。基线为 Bevy 0.19.1；审查前 `cargo check` 和 `cargo test --all-targets` 均通过。

## 结论摘要

项目的主流程已经可编译并有较完整的功能测试，但原有测试主要覆盖纯函数和协议 happy path，不能覆盖运行时输入异常、损坏存档、网络洪泛、状态切换和实体生命周期。高风险点集中在：

1. 外部数据边界：存档、网络区块更新、机器状态、浮点值和 RLE 数据没有统一的可信边界。
2. 持久化可靠性：直接覆盖目标 JSON，进程中断可能留下半个文件。
3. 网络资源上限：服务器区块日志、客户端待应用增量、聊天和网络状态缺少严格总量/速率约束；网络错误后连接资源可能残留。
4. 运行时 panic：空集合、无效浮点数、过期 UI 选择索引和若干 `unwrap/expect` 路径会把可恢复错误升级为进程崩溃。
5. ECS 生命周期：大多数游戏实体有 `InGame` 标记，空间场景也已纳入统一清理；但切换/断联时仍需要显式清空网络远端实体和传输线程，不能只依赖状态切换。

## 已实施的修复

- Rng、库存选择、玩家伤害、世界方块写入和 DDA 射线增加输入边界保护。
- RLE 存档拒绝未知方块 ID；机器状态读档限制槽位、数量、进度和浮点范围。
- 设置值读档归一化；JSON 改为临时文件写入后替换，避免直接写目标文件造成半文件。
- UDP 服务端/客户端加入区块日志、待处理增量和每秒区块更新上限；客户端应用前二次校验；拒绝/超时错误会清理连接状态。
- UI 中过期库存索引不再 panic；关键 egui context 获取改为可恢复分支。
- 工厂传送带排序使用 `total_cmp`，避免异常浮点值触发 `partial_cmp().unwrap()`。

验证结果：新增回归测试后共 44 个测试全部通过；`cargo fmt --check`、`cargo check`、`cargo clippy --all-targets -- -D warnings` 全部通过。`--smoke` 已完成加载、地面→太空切换、区块隐藏、太空清屏和保存断言（输出 `SMOKE_CHECK ... hidden=true` 与 `SMOKE_OK frames=481`）。

## 分阶段后续计划

### P0（本次完成）

覆盖崩溃、卡死、存档半写、网络无界增长和不可信输入。完成标准：新增边界测试通过，`cargo fmt --check`、`cargo check`、`cargo test --all-targets`、`cargo clippy --all-targets -- -D warnings` 通过。

### P1（建议下一轮）

补充 Bevy App 集成测试：Loading → Playing、Planet ↔ Space、返回菜单、空间站进出、断联重连；为 `InGame` 实体数量和资源存在性建立断言；增加真实窗口/无窗口 smoke 测试。

第二轮已落实：无窗口 smoke 已覆盖 Loading → Playing、地面→太空切换、区块隐藏、清屏和保存断言；新增飞行/弹道回归测试，并修复 NPC 场景动画初始化、泊入方向和交互提示生命周期。

### P2（性能与可维护性）

将地形生成/网格构建从主线程分帧或异步化；把网络 JSON 协议改为带版本/长度/压缩策略的二进制或受控编码；将存档写入搬到后台任务并加入备份/恢复；拆分过大的 UI/space 系统并减少每帧全量查询。

第二轮已落实部分 P2：大气飞行时降低区块生成/网格化单帧预算，避免高速跨区块造成长帧；新增独立飞船位置标记系统，避免继续膨胀主 HUD 系统。

### P3（安全与产品化）

加入联机身份/房间令牌、主机权限校验、编辑冲突策略和审计日志；为存档版本迁移建立显式 schema migration，而不是只依赖 `serde(default)`。
