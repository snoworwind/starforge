# 内容扩展分支可靠性审查

审查日期：2026-09-07。审查起点：`codex/bevy-content-expansion` 的 `e5c60be`，对照主分支 `19ec074`。

审查覆盖分支涉及的 16 个文件，重点跟踪物品数量、存档与星系归属、工厂供电、战斗及系统执行顺序。初始工作区干净，原有 90 项测试及严格 Clippy 检查通过，但仍存在以下未覆盖路径。

## 修复内容

| 问题 | 修复后的行为 |
| --- | --- |
| 机器积压产出在读档时按背包堆叠上限裁剪 | 生产计数独立于背包格子容量，保留合法产出；计数即将溢出时停止消耗原料。 |
| 物流先向空闲机器投料，该机器随后使用零需求电网的 100% 满足率 | 未参与本次用电核算的机器等待下一次分配，无电泵无法移动物品。 |
| 连续跃迁而不登陆会重复归档旧体素世界 | 只归档属于当前星系的世界；存档显式保存归属，旧档保留兼容推断。 |
| 跃迁后联机增量可能写入尚未替换的旧世界 | 目标星系增量保留在队列，等实际世界重建后应用。 |
| 太空中死亡后没有重生系统推进计时 | 在空间站出口附近恢复玩家和飞船，清除跃迁、脉冲和残留操控输入。 |
| 生物按水平距离攻击高处玩家，或攻击座舱内玩家 | 近战同时检查飞行模式及垂直距离；座舱内不受地面生物近战伤害。 |
| 已合并或超量回收的掉落物在延迟删除前被再次拾取，普通掉落物因正数延迟一直无法合并 | 同一帧后续处理跳过已移除实体；部分回收直接更新权威快照，并保护合并计数免于溢出；拾取延迟结束后允许合并。 |
| 相同材料重复出现在支付清单时可能少扣材料仍返回成功 | 先聚合并检查完整成本；不足、负数或求和溢出均不修改背包。 |
| Windows 保存中断后仅剩备份的世界无法在菜单中找到 | 世界与角色列表识别恢复备份并去重，沿用已有备份读档回退。 |
| F5 保存时拖拽物品不在持久化背包内 | 保存前将手持物品放回背包；空间不足时保留物品并提示先放下。 |
| 装备扩大氧气/护盾容量后充能按钮仍使用旧上限 | 按玩家当前装备的实际容量判断是否允许充能。 |
