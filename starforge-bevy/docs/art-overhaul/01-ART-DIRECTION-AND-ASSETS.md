# 01 · 美术方向、贴图、材质与资产生产

对应工作流B，依赖A的画质/版本/诊断契约；为C–J提供统一资产。下列分辨率和数量是首轮制作预算，须按屏幕占比、显存和视觉评审调整；不是当前资产盘点结果。

## 1.1 先建立可执行的风格规范

### 形态与构图

1. 以现有一格方块作为世界尺寸基准，记录玩家碰撞胶囊、眼高、机器占地、船体和门净空。建一个含这些实体的“尺度庭院”，外部模型全部在此校准。
2. 建立三档信息频率：远景识别轮廓（山脉、村庄塔、机器烟囱）；中景识别结构（屋檐、设备舱、管道和植被簇）；近景识别表面（磨损、粗糙度、接缝）。同一物体不能只有贴图噪声而缺中尺度构造。
3. 建筑采用正交体素主体与有限斜顶/圆角装饰；机器采用少量倒角和有功能解释的部件。倒角只用于视觉网格，不擅自改变体素射线命中。
4. 定义模块共同基准：统一枢轴、正面、底面、连接点、网格步长；建筑门向用枚举，机器端口用逻辑方向，禁止分别用作者任意朝向。
5. 做“允许/不允许”对照：允许大块色面、材质分层、有限高光；不允许所有表面同等噪声、全物体泛光、随处高饱和霓虹、风格相冲的原样外购模型。

### 色彩与亮度

1. 建立全局基础色：深蓝灰金属、暖灰岩石、偏暖木材；青色用于常规交互，暖琥珀用于能量和引导，危险色只用于危险。
2. 每生态制作色板：天光/雾/地表/岩石/植被/水/发光点/人工建筑8组；先看灰度明暗，再看饱和度，避免矿石与背景亮度相同。
3. 每色记录sRGB源值；进入shader后在线性空间计算。顶点色如果已经线性化，不得再次按sRGB转换；资产查看器明确显示源色和渲染色。
4. 设标准灯光（正午、阴天、暖夕阳、夜灯、室内）做同材质轮换。材质审批固定曝光；不要改环境补光掩盖坏albedo。
5. 发光分“标识”“照明”“能量源”三级，分别约定相对亮度、Bloom贡献和是否分配真实灯。普通白墙不能泛光；夜间灯牌保留文字边缘。

### 输出物

形成 `art/style-guide.md`、色板配置、尺度庭院场景、标准截图及一份材质模板。B01完成后其他流以该模板制作，不在各插件硬编码一套色彩。

## 1.2 资产目录、清单与可复现生产

每资产拟建manifest条目必须含：稳定key、用途类别、作者/来源/许可、源文件hash、导出工具版本、导出设置、运行时路径、色彩空间、尺寸、通道定义、采样器、预期加载大小、变体/LOD、fallback、风格版本。模型另含单位、朝向、pivot、bounds、材质槽、socket、碰撞代理、骨骼/动画清单；纹理另含mip和压缩策略。

操作顺序：

1. 从代码实际引用和 `assets/` 反查资产清单，列“存在/忽略不入库/缺失/未引用/许可未知”，不只扫描文件扩展名。
2. 将原始制作文件与运行时导出物分离；源文件如体积大，决定版本化存储策略并给下载清单与hash，不能只留一个作者电脑路径。
3. 写Rust资产检查工具，逐条解析manifest，检查路径大小写、父目录穿越、引用缺失、纹理尺寸、格式、模型bounds、动画命名和许可字段。
4. 导出流水线对相同源hash+导出参数产出相同工件；若工具本身含时间戳，hash以规范化后的有效内容为准并记录原因。
5. 运行时加载失败显示稳定fallback并日志去重；必需资产缺失在加载界面说明，不能无限黑屏。开发版显示粉色诊断材质，发行版用风格一致占位但保留错误报告。
6. 热重载先验证整组依赖，再原子替换句柄；旧纹理还在GPU使用时不提前删；失败保留旧版本并显示原因。
7. 打包器从manifest收集依赖和署名，测试exe旁assets路径；不要依赖源仓库工作目录或调试时的自动复制掩盖缺包。

注意：仓库现有外部船/站/地球素材被忽略；必须同时提供“仅仓库素材可运行”与“完整素材视觉验收”两种状态。不能把未下载导致的占位图写成最终效果通过，也不应未经核实删除CC-BY署名。免费使用与允许修改/再分发是不同字段。

## 1.3 纹理系统升级路径

### 现有图集的兼容问题

旧Atlas注册顺序决定tile index，单格16×16，全图256×256。第一步冻结 `block key → face role → legacy tile key` 映射和回归样本；之后引入稳定 `SurfaceMaterialId`，让纹理扩容不改变方块ID、存档或配方。

### 推荐双路径

- 精致模式：纹理数组优先，每层独立tile和mip；普通块64×64起，关键表面128×128，少数近距重点可256×256。保持像素分区和大形体，不改成照片贴片。
- 经典模式：保留16×16风格资产，独立Nearest策略。远景仍允许经过艺术审核的颜色mip/远景材质降低闪烁，不要求所有距离都无过滤。
- 若数组兼容/采样布局原型不通过，使用**逐tile独立制作mip并预留边界扩展的图集**作为fallback；明确最大有效mip，不能给整图直接做普通缩小。

实施步骤：

1. 为每face指定上/侧/底、旋转规则、可平铺边界和随机变体组；UV基于单格局部坐标，不用依赖图集绝对位置的硬编码。
2. 写离线转换：源tile → albedo/normal/ORM/emission → 各自mip → 数组/图集工件。记录每层key，不把数组顺序当业务ID。
3. 对sRGB颜色在线性空间缩小后编码；normal mip先还原向量、平均再归一；roughness mip评估高光闪烁，必要时做法线方差补偿；alpha foliage保持覆盖率。
4. 图集边界采用extrude与gutter，给出每一级实际padding；采样选正确mip后边界仍不能读邻tile。测试所有tile连接和掠射角；禁止仅以“加半个texel”宣称解决全部mip问题。
5. 对不连续UV使用正确导数或显式LOD策略，在格边界避免frac后导数突变；切换到triplanar的表面单独审核代价和方向。
6. 水、玻璃、植物、发光区域脱离全局solid材质；opaque尽可能剔背面，cutout只给需要的几何，双面只给薄片。
7. 增加灰阶/UV/法线/roughness/metallic/alpha/texel density调试视图。将旧图集模式保留到全方块覆盖验收完成，再评估移除兼容适配。

### 减少重复感

每主材质做3–6个微变体，共用相同边缘规则；以稳定整数世界格+face hash选择旋转和变体，不用Entity ID、世界加载顺序或渲染帧号。层理、木纹、机器铭牌不能任意旋转。增加低频区域色差、潮湿/苔藓/积灰mask，强度约束在可读范围；宏观噪声坐标跟随逻辑世界，不能跟相机游泳。

相邻矿石保持矿物形状可辨识；稀有资源纹理不要与随机装饰使用同形同色。采矿裂纹是独立覆盖层，按进度有限阶段更新，不每次命中整片重生成贴图。

## 1.4 PBR通道与材质家族

工程统一约定：base color和emission为颜色语义，normal、AO、roughness、metallic为线性数据。对glTF导入按规范核对：metallic-roughness纹理G为roughness、B为metallic，occlusion使用R；本项目可将三者装为ORM工件，但不能假设所有源资产都已如此打包。法线方向、单位和alpha按 [Khronos glTF规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)核对。

下表范围为材质审稿起点，不是引擎保证或物理测量值：

| 家族 | 初始roughness范围 | metallic策略 | 必做细节与验收 |
| --- | --- | --- | --- |
| 土/砂/盐 | 0.75–1.0 | 0 | 大颗粒层次、低高光；砂坡掠射角不闪烁 |
| 岩石/玄武岩 | 0.6–0.95 | 0 | 裂缝、层理、断面；不能全靠AO涂黑边 |
| 草/苔藓 | 0.75–1.0 | 0 | 顶面与侧面过渡、根部暗部、少量色差 |
| 木/板材 | 0.5–0.85 | 0 | 顺纹/端纹不同、接缝有方向、屋内外统一比例 |
| 涂漆设备 | 0.3–0.65 | 漆0，露底mask接近1 | 边缘有限磨损、缝线、标识；不整机金属化 |
| 裸金属 | 0.2–0.55 | 接近1 | 有环境反射才能审；拉丝方向一致 |
| 玻璃 | 0.02–0.2 | 0 | 厚度边缘/反射可读，透明与碰撞一致 |
| 水 | 0.04–0.25 | 0 | Fresnel、吸收、浅水过渡，不用金属度伪造水亮度 |
| 冰 | 0.1–0.45 | 0 | 裂纹/气泡深浅层，不能像蓝塑料 |
| 雪 | 0.8–1.0 | 0 | 雪面大形/阴影、抑制微亮点闪烁 |
| 晶体 | 0.12–0.4 | 通常0 | 刻面法线、内部发光mask、有限灯光贡献 |
| 熔岩/能量源 | 壳与液体分离 | 壳0 | 亮区保色、黑壳覆盖、Bloom不吞轮廓 |
| 叶/菌/膜 | 0.55–0.95 | 0 | alpha轮廓、背光近似、背面normal、阴影一致 |

每族制作标准球、方块、斜坡、薄片、室内物件。法线贴图只改变微表面，不企图把平板变成有轮廓的设备。纹理里保留细微局部遮挡，去掉固定太阳方向的大块烘焙阴影，防止与昼夜光照冲突。

## 1.5 纹理/模型/图标的具体制作清单

### 方块及环境纹理

1. 从 `data.rs` 自动枚举所有方块的face角色，生成覆盖报告。README称87种只作历史参考，以实际枚举为准。
2. 按“土石→草木→矿物→建筑→机器→液体/特殊”六批制作；每批至少有白天、夜灯、掠射、远距、经典模式图。
3. 规划90–140组独立表面材质（共享父材质不重复计数），每组按需要提供albedo/normal/ORM/emission；不是强制每种块四张满尺寸图。
4. 每生态补2–4种地面碎屑、2种岩石轮廓、3种植被簇；跨生态共用基础几何，通过受控色板和形态差异避免复制感。
5. 设备屏幕/灯条/铭牌以atlas或trim sheet共享，固定最小可读字号，屏幕内容不会误导玩家状态。

### 图标

1. 由物品key建立完整清单，库存、快捷栏、掉落标识、配方、科技和教程引用同一key。所有物品含fallback，不能用emoji当核心图标。
2. 基础物品选手工像素/矢量构形或离线模型渲染一种主路径；模型渲染统一正交相机、三分之四角度、背景透明、灯位和占框比例。
3. 64×64为UI主导出，提供32/128按DPI选择；轮廓至少占画布约70%，数量角标留固定安全区，透明边缘避免暗色halo。
4. 分类用轮廓和角标，不只用颜色；相似矿石/中间件至少有一个强形状差异。禁用、选中、不足、研究锁定状态交给UI装饰，不把状态烘进同一图标。
5. 自动生成物品联系表，检查漏图/重复图/模糊/偏心；灰度和色觉模拟下进行识别测试。

### 模型与模块

1. 建模网格、碰撞网格、阴影代理分开。导出前应用缩放、检查负scale和法线、退化面、非流形、UV重叠是否有意。
2. trim sheet共享工业倒角/边框/槽线；高频螺钉多数使用normal或批处理小件，避免每颗螺丝一个ECS实体。
3. LOD0/1/2和远距impostor按投影面积设初始阈值，至少保持主轮廓、主要色块、灯光位置；面数下降不能让门窗瞬间封死。
4. 原型预算：近景普通机器约1–8k三角、角色约3–15k、重点船约20–80k，聚落按可见模块总数预算；在本项目实际GPU上复核后调整，不直接作为所有模型统一上限。
5. 所有模型提供单位/朝向/pivot/sockets检验图；船体增加驾驶位、引擎、武器、登船点、起落架、相机避障点；角色增加头/手/脚/背包锚点。

## 1.6 预算和压缩

计算格式：未压缩RGBA8二维纹理近似 `w×h×4` 字节，完整二维mip约再乘4/3；数组再乘层数。三维纹理按 `w×h×d×每体素字节` 和实际mip链求和，不能机械乘二维4/3；HDR、深度、normal格式按实际字节和对齐计。

例如128×128 RGBA8×128层带二维mip约10.67MiB；四组同格式数组约42.67MiB，只是纹理示例，不含GPU副本/上传缓冲。192×32×192单通道R8密度约1.125MiB；若换RGBA8则约4.5MiB，必须按实际工件格式登记。

操作：先按有效画质构建纹理预算表→把常驻、按星球、按区块、相机history拆开→统计峰值而非平均→验证设备支持后选择压缩（例如目标PC支持的块压缩）→不支持时加载受控低分辨率未压缩fallback。KTX2/压缩转码、16位纹理和各向异性均先核对Cargo features和锁定Bevy加载器，不能只改文件后缀。

不得用4K纹理提升一格墙，不能让每生态保留整套不再访问的GPU资源。对normal/ORM压缩做斜光对照，尤其晶体、薄叶和UI图标，体积缩小不等于质量合格。

## 1.7 验收与常见修复步骤

| 现象 | 首查 | 修复顺序 |
| --- | --- | --- |
| 每格边缘异色线 | atlas padding、mip、UV导数 | 可视化UV/mip→独立tile mips→验证极小mip→必要时切数组 |
| 石头像塑料 | roughness/色彩空间/法线强度 | 固定曝光→显示roughness通道→还原线性→降低微法线和高光 |
| 叶片远处消失 | alpha mip覆盖率 | 对每级统计coverage→修正阈值/mip→验证阴影同轮廓 |
| 金属变纯黑 | 环境反射、metallic通道 | 放灰球对照→恢复环境图→查B通道与贴图线性 |
| 图标黑边 | alpha预乘约定、缩放 | 检查透明RGB→一致预乘→正确导出和采样 |
| 模型近看正常远处乱闪 | 细面、mip、高光、LOD | 去共面→normal方差/roughness→LOD轮廓→时间序列复查 |
| 新资源只在开发机显示 | 大小写/路径/忽略文件 | manifest依赖审计→干净目录安装→可见fallback→补包 |
| 换色影响所有实例 | 共享材质被直接修改 | 区分共享材质/实例参数→有界variant→测试多人不同外观 |

B的完成条件：全方块/物品/机器注册覆盖报告无漏项；标准材料庭院和联系表通过；冷热加载、错误资产、最小素材包、DPI图标均有证据；没有无来源/许可不明的最终交付资产。
