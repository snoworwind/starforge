# 02 · 渲染、光影、大气、云与合成

对应D/E和F中的水表现；依赖A的视觉帧与质量解析、B的正确材质。以下所有新渲染通道先做最小原型和GPU计时，验证锁定版本接口后才能接入主场景。

## 2.1 从正确性开始，而非堆效果

现有HDR、固定EV100=13、AtmosphereEnvironmentMapLight、SSAO、ContactShadows、Bloom都是基线的一部分。D01创建可切换单项的材料庭院和封闭房间，保存无后处理/仅直射/仅环境/仅AO/最终图，建立颜色与能量路径图。

操作步骤：

1. 记录主相机、像素模式中间目标、UI相机和摄影相机的format、尺寸、clear、曝光与tone mapping设置。
2. 从源albedo到最终窗口逐段确认sRGB→线性→光照→HDR合成→显示变换，仅在正确位置转换一次。
3. 检查天空/云是否在同一曝光尺度。禁止用一个针对EV13手调的“云亮度常数”去适配所有曝光档。
4. 建立渲染能力矩阵：深度采样、法线、运动向量、纹理数组、3D纹理、存储纹理、HDR格式、时间戳、MSAA、可用AA路径。不能仅看显卡名猜支持。
5. 给每通道命名、计时、可视化输入/输出、说明fallback。shader编译失败时显示明确诊断并回到有效路径，避免黑屏和每帧重新编译。
6. 保存参数档和测试场景；修正现有源码/README相互矛盾处，但保留光照修复原因和回归场景。

## 2.2 曝光、色调映射、颜色分级

### 固定曝光先稳定

以当前EV13为正午起点，调材质和光源后，建立正午/黄昏/夜晚/洞穴/室内/轨道的曝光与补光曲线。默认先用有上限变化速度的场景曝光策略；跨区域用连续权重，灯光强度和曝光不可互相补偿成不可维护参数。

具体步骤：

1. 配标准灰卡、白卡、黑卡、发光卡；截图读取其线性和显示亮度，确认没有普通白墙被Bloom吞没。
2. 给太阳照度、太阳盘可见亮度、环境补光、灯具发光、曝光定义独立职责。F3 slider显示单位/生效范围。
3. 用屋外→屋内→洞穴往返曲线验证最暗处可导航，同时保持夜色和洞穴深度。室内亮度优先来自遮挡正确的照明，不能只大幅提高全局环境光。
4. 若引入自动曝光，作为后续可切换路径：先可视化对数亮度直方图和计量mask，设置与真实场景一致的EV范围，排除UI/太阳极亮点影响，限制上下界和适应速度；保留手动曝光。
5. 摄影模式允许固定曝光和调色，退出恢复用户设置；联机摄影不暂停服务器模拟。

注意：现有注释明确记录旧自动曝光直方图区间和太阳增益曾造成问题。不能只加回AutoExposure并宣称修复亮度。曝光切换导致的history变化要向TAA/云历史传递曝光比或重置；避免夜视一开云层残影发亮。

颜色分级先提供中性、暖夕阳、冷夜间的受控参数，不默认强色差/胶片颗粒/镜头脏污。科学可读性优先：氧气警报、矿物、敌人颜色不能被生态LUT变得不可辨。

## 2.3 太阳、月光与动态阴影

1. `CelestialLighting`统一太阳方位、光传播方向、盘的位置、大气光源和云光线方向。做正午和低太阳方向箭头调试，避免相函数使用相反向量。
2. 太阳高度接近地平线时平滑调整光色/照度，避免整帧切灯；多星体方向若有扩展，先指定主阴影光，不能每颗星都开完整级联。
3. 以相机近中远关键对象制定级联覆盖。近处重点是脚底、机器底座、台阶、门框；中景是聚落；远景用廉价遮蔽/地形自阴影感，不无限拉长高精阴影距离。
4. 建档位化阴影贴图、级联数、距离与过滤参数。起点低1024、中2048、高4096，超高仅在预算通过后增加；尺寸是建议，不是对Bevy任意级联配置都有效的保证。
5. 调bias前以一格立方、薄叶、斜坡、屋檐、移动角色分别检查acne和peter-panning；记录world-space尺度，不能以超大bias掩盖错误normal或曲率。
6. 主渲染与阴影/prepass共享相同曲率、风动、LOD选择与cutout阈值。若无法共享一个shader入口，至少共享数学函数并用自动对照测试约束。
7. 为稳定阴影研究投影texel对齐/级联缓动是否引擎已提供；在锁定版本允许范围内配置。不能绕开Bevy缓存每帧新建阴影管线。
8. 对不重要装饰按距离关闭投影，对重要大树和建筑用阴影代理；关闭的是成本，不是近景接触可信度。

验收：朝向/移动/转头各30秒视频无明显阴影游动；夕阳长影方向正确；树叶影与风同步；云影与太阳遮光一致；穿过级联边界不出现亮带。

## 2.4 AO、洞穴遮挡与间接光

已有体素corner AO、SSAO、接触阴影可能叠得过黑，必须各自定义负责的尺度。

1. 将顶点AO从“乘死在albedo”逐步转为可识别遮蔽信号，先保旧视觉兼容；直接光和间接光的调制要有意设计，不能让三层AO同时把直射角落压黑。
2. 保留corner AO用于方块接触，屏幕AO用于模型落地和中小结构。对半径/厚度/强度随场景尺度校准，提供各项单独开关。
3. 验证SSAO实际需要的prepass资源与sample count；相机配置变更后缺normal或深度时有诊断，不能“组件存在就算有效”。
4. 封闭洞穴/建筑不能靠SSAO阻断整个天空光。新增粗粒度天空可见度/室内体积或有限探针作为环境补光权重，记录更新半径和失效规则。
5. 首选低成本环境图+局部探针/区域补光；全动态GI、体素锥追踪、复杂辐照度缓存仅为预算外研究项，不能绑住主工程。
6. 玩家拆墙/挖洞后，遮挡和局部补光按dirty区域更新；避免每帧全世界重新求解。探针捕获含时间预算，不反复捕捉自身可见探针代理。
7. 金属机器和玻璃需要反射环境。室外天空环境与室内探针过渡，SSR仅补充屏幕可见反射，离屏必须fallback。

验收：封闭屋内不被天空全亮照透；开门后亮度有合理变化；矿洞可用头灯导航；脚底无大黑圈；转头不让整台机器突然变黑；旧AO回归测试继续有效。

## 2.5 局部灯光与发光物

现有灯池遍历周围方块找最近灯、每0.5秒更新，机器也有灯池。改为统一视觉灯候选注册表，插入/移除由方块/机器revision驱动。

1. 每候选记录stable_id、位置、颜色、强度、范围、重要性、是否允许阴影、状态来源。
2. 按投影影响、距离、玩法重要性和视锥打分；加入保留时间和替换滞回，防止两个等距灯反复抢槽。
3. 首轮总有效局部灯低/中/高8/16/32，其中投影灯0/1/2起；不是每机器32灯。实际预算与Bevy光源支持、cluster成本一起确认。
4. 光源位置放在出光面外侧并和模型socket绑定；点光漏墙时先检查范围与投影，非投影远灯仅提供有限补光。
5. emission可常驻，真实灯按预算分配；没有灯槽仍保留设备自发光，但不伪造照亮整片地面的效果。
6. 支持灯罩、局部光晕、有限体积光束；体积光只给头灯/探照灯等重点，普通灯不都开光柱。

验收：百台机器和洞穴晶体压力场景无周期CPU尖峰、无闪灯；停电后只关对应活动发光和工作灯；夜间脚边小灯不把天空曝光压黑。

## 2.6 天空与大气

1. 继续以 `PlanetScaleProfile` 为唯一高度尺度源；局部渲染球壳的center、radius、datum统一更新。云底420等数值只由配置读取。
2. 将16生态天空设计转为可调大气预设：散射颜色、浑浊度、雾密度、光源颜色、夜空底色；先保物理合理梯度再做风格偏移。
3. 做地平线检查：低角度太阳、视线上穿大气、从轨道看薄边、极低海拔和高空；不能用纯黑ClearColor硬切割大气。
4. 距离雾与大气散射明确分工：局部灰尘/湿度遮蔽用天气雾，远程空气透视由统一透射处理；避免同一距离重复衰减。
5. 星空按太阳光/大气厚度/曝光渐显；恒星不产生与背景同等噪点，白天不透星；星系方向稳定，不跟相机旋转。
6. 极光、流星、闪电分别指定深度层级和被云遮挡关系；雷暴闪电可照云但不无条件让全场景每帧变白。
7. 多星球天空资源按可见性和距离加载；轨道球体大气halo不互相穿叠成白圈。

## 2.7 体积云：总体技术路线

现有云为球壳raymarch，不从零重写。E01先绘制密度切片、射线区间、depth截断、透射T、散射L、采样次数、光向量；验证数学正确性后按下列层次替换。每一步保留现有路径作受控fallback，直到相应新路径验收。

### A. 云场与形态

1. 将“宏观天气图、云类型高度曲线、基础形状噪声、细节侵蚀噪声”解耦。天气图驱动覆盖、厚度、对流发展；噪声只雕形，不承担全球天气状态。
2. 做4类主形：低积云、层云、高卷云、雷暴塔状云；各有底平度、顶部蓬松程度、厚度和破碎度。异星孢子/灰霾可用薄层体积，不所有生态套棉花团。
3. 低频形状采用连续分层噪声，细节按距离衰减；高频侵蚀应主要影响边缘，内部保持厚实，不把整云啃成泡沫。
4. 以高度剖面控制base/top，垂直方向不能和水平一样Repeat造成顶底绕回。即使采样器整体Repeat，也需在构建/采样明确屏蔽垂直边界。
5. 当前192×32×192纹理保留为原型，比较缓存离线生成、后台生成、GPU生成的真实启动耗时再选；不盲增到512³。
6. 种子使用稳定世界/星球ID；密度工件按噪声版本和biome缓存；风平移用累计相位取模和高精时间，长时间运行不因f32绝对时间失精而跳动。
7. 避免camera-relative球壳中心移动把天气带着玩家走：宏观采样锚定逻辑星球坐标，相机相对量只用于GPU计算精度。北极、经线接缝、局部切平面更新均有测试。

### B. 射线积分与照明

1. 将球交算法测试分为相机在云下/云内/云上/球外、视线背离、切线、穿过内球、地表挡住远侧等；返回多个有效区间或证明可只取首段，避免漏掉远侧云层。
2. 不把太阳光步长固定为“55×4”适配所有云厚度；按出云距离、太阳高度和预算分配步长，设置最大路径并清楚说明近似。
3. 用Beer–Lambert积分：单步透射 `exp(-sigma_t*density*ds)`；光学厚度单位统一，改变步数不能显著改变总亮度和覆盖。
4. 保留HG等相函数近似，校准g与光向量；银边来自前向散射和透射结构，不是全边缘描白。低太阳角度云底应暗、边缘可暖。
5. 先用成本受控的多次散射近似改善暗部，参数写明艺术近似；不能标成真实多次散射路径追踪。
6. 维持输出 `(L, 1-T)` 与预乘alpha一致；合成 `L + T*background`。离屏路径中不能又乘一次alpha，避免薄云变灰边。
7. 根据密度/透射提前终止、空区域跳步；用误差图校验稀薄丝云是否丢失。进入云内时抑制稀疏大步造成的穿帮。

### C. 分辨率、降噪与历史重投影

当前render_resolution兼容字段不等于有效降采样。E03新增真正的每相机云渲染目标，并把UI改成生效的比例/档位。

1. 为每相机分配散射、透射、代表性云深度/置信度、历史帧和可选矩的纹理；按实际格式计算峰值显存。避免为隐藏地图/预览相机分配整套云history。
2. 首轮低/中/高：半宽半高+16–24步、半宽半高+32–48步、全或半宽高质量重建+48–64步；半宽半高是1/4像素，文档和UI写清。超高64–96仅在同步修改上限、验证shader和预算后启用，现有MAX_STEPS=64不支持96。
3. 每像素用稳定蓝噪声/帧序列抖动并提供采集固定序列。不能用固定屏幕噪声令转头时云形状爬动，也不能每帧纯随机制造闪烁。
4. 重投影记录前帧相机矩阵、visual origin、风位移、曝光、代表性云深度。云移动没有普通实体motion vector时，用天气场平移补偿；不能只重投影静态背景深度。
5. 以深度不一致、遮挡解除、天气变化、相机快速转动、透射差异降低history权重，做邻域clamp，防止船身后拖出灰尾。
6. 地面/太空切换、传送、FOV改变、resize、DPI、质量档、曝光大跳、暂停恢复、world_epoch变化强制重置；small camera jitter不能每帧误触重置。
7. 双边上采样结合scene depth和云深度/透射，轮廓边缘选择正确样本；放大草叶、天线、船翼和山脊检查亮边。
8. 多相机history独立，以camera稳定标识隔离；摄影分块高分辨率输出需要冻结时间和统一投影offset，不把一块图的history喂给另一块。

### D. 云影、天气耦合与跨尺度

1. 用宏观密度沿光方向生成低频云透射阴影图，稳定世界坐标和相机环形覆盖，分帧更新。首轮512/1024分辨率按档比较。
2. 云影应主要衰减太阳直射，不把环境光、灯光和UI一起压暗；阴影边缘随云高度/厚度柔化，避免固定硬边投影贴地滑动。
3. 太阳近地平线时限制投影范围和采样病态值，平滑降级为宏观天光变化，不让整地表拉出无限条纹。
4. 地面云与太空云共用星球天气图、时间和旋转相位。地面用局部高质量体积，远轨道用投影云图/薄壳；对比同经纬地标，颜色/覆盖/方位要对上。
5. 在统一高度带内交叉淡出，防止两个相同云层能量相加变白。保留再入/离开滞回，切场景时先准备目标资源再交接。
6. 穿云飞船逐渐被体积遮挡，座舱UI仍清晰；云内雾和全局天气雾不能双算。雨强与云覆盖、湿润和雨声来自同一WeatherSample，非逐帧互相猜测。
7. 雷暴短时局部照明写入云散射，不靠全屏白片代替；低闪烁模式降低强度和频次但保留危险提示。

### 云验收场景

固定清晨逆光、正午顺光、夕阳、无月夜四光况；coverage=0/默认/1，density=0/默认/高；相机地面/底部边界/云内/顶部边界/轨道；静止10秒、慢转30秒、高速穿越、掉头再入。对比16/32/64步平均亮度和形态，不应随步数大幅变暗；保存history置信度和重置原因。目标是整段运动不闪不拖，不只一帧好看。

## 2.8 水、玻璃、冰、熔岩

水由F负责材质与岸线，D负责scene color/depth与反射合成，E提供云透射接口。

1. 从水材质和顶点颜色/alpha链开始审，统一一个着色来源；水metallic设为非金属并通过Fresnel和反射获得亮度。
2. 先做两层低振幅滚动法线，后评估顶点波浪；体素水逻辑平面与可见波面偏差须有限，避免玩家在“空气”中游泳。
3. 用水表面与场景深度差估计水深，进行吸收/散射色；reverse-Z必须正确还原线性距离。透明地物未写深度时采用受控fallback，避免负深度。
4. 屏幕折射使用不含当前水的场景快照，屏幕外/天空/深度反转时拒绝无效样本；不能采样正在写入的目标造成反馈。
5. 高档SSR或局部平面反射作为可选；不支持或离屏时天空/探针fallback。反射相机排除UI、反射面本身和不必要粒子，限制更新频率。
6. 泡沫由岸线接触、浅水、障碍和运动事件驱动，不随机铺白点；shore mask随玩家填海/挖岸dirty更新。
7. 水下切换用稳定高度/滞回，统一雾、色调、气泡、表面背面和音频；相机贴水面不每帧来回切。
8. 玻璃先保证透明排序、背面和碰撞一致，厚玻璃用有限吸收和环境反射；不要每窗一套屏幕折射pass。
9. 冰使用裂纹/气泡层，远距回归粗糙材质；熔岩拆黑壳和流动发光区，热扭曲强度限制在轮廓仍可判断的范围。

## 2.9 抗锯齿、清晰度与后处理

1. 当前Msaa::Off，D01先确认是否存在其他AA实际接入。建立thin cable、树叶、矿纹、远格线、船天线、UI字体测试画面。
2. 在锁定版本提供的FXAA/SMAA/TAA等候选中原型比较，明确支持与限制。不要同时打开互相冲突的MSAA/prepass/时间重建路径。
3. 普通模式建议先选可靠空间AA作低档，时间AA仅在motion/历史/透明问题验证后作高档；像素模式使用独立像素对齐规则，UI保持原生分辨率。
4. TAA不能修复材质无mip、阴影抖动或坏LOD；先解决空间输入，再调history权重和有限锐化。反应mask覆盖发光闪光、透明/VFX变化。
5. UI在tone map/3D模糊后渲染；准星、库存数字、小地图文字不随景深或运动模糊变糊。
6. Bloom从高亮HDR提取并限制扩散；DOF/运动模糊/色差默认关闭或极弱，摄影可单独选。镜头污渍和暗角不覆盖关键HUD。
7. 动态分辨率根据平滑GPU耗时调节，设上下界和滞回；降低内部分辨率时同步云/SSR/history重建并标记重置，不反复抖动档位。

## 2.10 本领域故障定位流程

黑屏先查目标format和shader编译→再查uniform/bind group→再查view和尺寸→最后查效果参数。泛白先关Bloom并锁曝光→查云预乘和重复tone map→查environment/ambient重复补光。黑边先显示depth→查透明排序→查曲率主/prepass不一致→查双边上采样。卡顿先看CPU生成/上传→再看GPU pass→查ray步数、屏幕覆盖和带宽；不能只删一半粒子猜原因。

所有修复提交附复现机位、开关组合、输入缓冲视图、修复后同路径视频和GPU/CPU指标。高级通道失败可以按已规定fallback交付该硬件档，但必须在质量UI与能力报告显示其实际状态。
