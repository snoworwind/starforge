# 03 · 地形、生态、植被与程序化建筑

对应C/F/G。首要约束：视觉升级不能改变已保存的玩家修改、已领取奖励、兽群死亡掩码、机器库存和联机权威世界。新增会改变碰撞/可采资源的内容必须版本化；纯装饰应能随画质开关安全去除。

## 3.1 体素网格与近景质量

### 分桶与材质

1. 在 `build_chunk_meshes` 周围建立MeshBuilder接口，先输出与旧网格一致结果，保留边界/绝对坐标/AO测试。
2. 分类opaque、cutout foliage、transparent liquid/glass、emissive、special geometry，不再让岩石为草叶统一双面Mask承担成本。
3. 每顶点明确position、normal、UV/材质层、tangent、AO/颜色来源；渲染ID独立于逻辑block ID。每类face朝向和normal一致，反面植被作显式处理。
4. 贪婪合面只在材质、朝向、UV平铺、AO/光照、透明类别和变体兼容时合并。若AO四角不一致，不可粗暴跨越合成一张面。
5. 合并面UV按世界格重复，不能把一张砖纹拉满二十格；texture array和正确导数优先，不能产生远距tile抖动。
6. 对相邻face内部消隐、透明水内面和共面边缘单独处理；保留水/玻璃间材质边界的正确规则。

### 边界、AO与编辑

1. 网格生成读取一圈必要邻居halo，边界未加载时使用确定性基础生成+已知修改快照，而非永久当空气。
2. 修改边界方块时标记自身与受影响邻居mesh、AO、LOD、装饰和小地图dirty；涉及角AO时包含对角邻居。
3. 每个异步结果携带区块/邻居revision和world_epoch，提交前复核；支持快速连续挖掘时合并队列，取消过时任务。
4. 半透明重建保持旧有效mesh至新mesh就绪；CPU换数据和可见性同帧原子完成，不出现一帧空地。
5. 破碎/放置预览使用明确offset或专门覆盖通道避免z-fighting；不能永久抬高整个地形来遮裂缝。
6. 地面继续保持与物理一致的近距平坦区。新增倒角、坡面、台阶是纯视觉还是新碰撞形状要逐类登记，不让玩家踩空或射线命中不可见面。

验收：连续挖穿四区块交角、地表放灯、切断树根、填海、搭高塔再离开返回；网格/阴影/LOD/地图一致。正常模式下1格边缘清晰，斜看地面不闪成棋盘。

## 3.2 LOD与地面到轨道的一致性

现有层级LOD与legacy far fallback并存。C01先记录每种mesh的覆盖半径、flat/full曲率范围、可见性、顶点来源和更新频率，再作修改。

实施步骤：

1. 定义屏幕误差预算，按FOV、viewport高度、距离和节点误差选LOD，不能只用水平距离固定阈值。加入升降级滞回和至少数帧保留，避免边界抖动。
2. 明确“父节点保留直到所有需要的子节点可显示”的替换协议；子节点未就绪时不提前挖空父节点。
3. 邻接LOD相差限制在可拼接范围，采用transition strip、裙边或专门缝合面之一并记录适用处；裙边不得封住可见大洞或悬崖入口。
4. 近/远颜色都采自统一材质族和低频地表信息，在相同线性空间求平均；水、发光矿物和建筑轮廓不被简单平均成泥灰。
5. 改造 `far_surface_sample` 和星球纹理输入，共用高度/表面摘要；玩家大工程以稀疏修改摘要更新近中远和地图，不能离远后基地变回山。
6. 审查当前LOD为地表近似的范围，洞穴、悬空岛、桥、塔等需要重要结构代理；不能声称当前surface mesh已具备完整三维体素LOD。
7. 曲率主渲染/prepass/阴影/法线统一，normal用相应变换或导数修正，不能只弯position导致山坡受光错误。
8. 当层级LOD足够覆盖时，收敛legacy far mesh为明确fallback；避免两套都透明覆盖同一地面。移除前保留失败注入测试。
9. 太空星球纹理、局部地图、地面采样使用同一逻辑地貌版本；轨道球体淡入时坐标/太阳方向/海岸线一致。
10. 飞船高速移动按预测路径预取，队列近处优先、旧方向任务降权；GPU上传设字节预算和时间预算，不能只“每帧两个区块”。

验收：固定路径沿地面→山顶→420/780云带→1800再入边界→2400离开边界→轨道绕行→原基地；视频检查轮廓、海岸、地标、太阳方向与云图连续。记录p95/p99帧时而非只看平均FPS。

## 3.3 地貌从噪声升级到空间构图

不立即改旧世界 `height_at`。为新生成版本依次加入：大地貌骨架→侵蚀/沉积近似→局部坡面层次→水岸/道路约束→生态装饰。

1. 大尺度：山脊、谷地、盆地、海岸、台地，控制每种地貌的可通行比例和地平线轮廓；避免全地表同频率起伏。
2. 中尺度：悬崖层理、冲沟、岩柱群、陨石坑内外缘、火山口与熔岩流迹；有坡度/高度/湿度因果，不是独立叠加所有噪声。
3. 小尺度：碎石、根部、泥水线、苔藓、雪堆、裸土，遮蔽基础方块的机械重复，但不盖住可挖矿物提示。
4. 洞穴分入口过渡、通道、大厅、资源点和危险区；用局部光/空气透视带深度，不把每处涂同一种灰黑。
5. 地表坡度与资源/植被/建筑各有约束mask；全部共享同一采样数据，避免各流计算不同坡度。
6. 河流/瀑布/动态海浪若会改水逻辑，列单独变更；本项目主体可先用地貌生成的河槽+静态逻辑水+视觉流向，不承诺完整水动力模拟。
7. 保留高度范围和WORLD_H限制。山峰/建筑顶若超96层，先拒绝或降低生成高度；扩大世界高度是额外迁移/性能工程，不能只改常量。

## 3.4 16生态逐一制作计划

| key / 生态 | 地形与表面 | 植被/细节 | 天气、水、建筑特点与注意事项 |
| --- | --- | --- | --- |
| lush 翠绿 | 清楚山脊与河谷、草土侧面过渡 | 分层树冠、草簇、花、树根和倒木 | 积云与阵雨、岸线；温带聚落。避免满地等距草点、树挡门 |
| desert 荒漠 | 沙丘迎风背风坡、岩台 | 稀疏枯木、耐旱灌丛、风蚀石 | 薄云/沙尘、避风墙和遮阳；沙尘能见度有玩法下限 |
| frozen 冰封 | 雪面/裸冰/岩石分区、冰川裂隙 | 冻枝、雪团、风吹雪脊 | 层云/雪、建筑保温基础；白雪保留纹理不过曝 |
| volcanic 熔火 | 熔岩黑壳、冷却纹与玄武柱 | 焦木、喷气孔、岩屑 | 灰云/热浪、隔热建筑；亮熔岩不过量Bloom，碰撞危险边界可辨 |
| alien 异星 | 紫色地表与异形岩脉 | 宽叶/膜状植被、孢子荚 | 异色薄云/毒孢子、防护舱；避开全部青紫导致资源混淆 |
| ocean 海球 | 海底分带、岛礁、沙岸 | 水草、珊瑚形装饰、漂浮物 | 水深色/浪花/海雾、桩基聚落；水草不假装可采，落点不在海中 |
| crystal 晶簇 | 冷灰底岩与晶脉 | 大小晶簇、碎晶、少量冻草 | 清冷天空与晶雾、采掘营地；灯池限额，晶体mask不统一透明 |
| fungal 巨菌 | 潮湿软土、根系台地 | 多层菌盖、菌丝、倒伏菌杆 | 低云/微孢子、抬升栈道；菌盖俯仰都应有结构，不漂浮 |
| ashen 灰烬 | 灰层/烧结地面/断崖 | 焦枝、火山灰堆、熄灭火口 | 灰雾层次、废弃工业；灰画面须保前中后景明度差 |
| amber 金珀 | 金黄沙海、琥珀矿岩 | 琥珀簇、耐旱矮植 | 暖天冷影、风蚀遗迹；黄色矿与沙地用轮廓/高光区分 |
| ferrous 磁暴 | 铁红与冷钢灰分区、金属脊 | 磁性碎屑、锈色结壳 | 电弧/磁暴云、接地工业设施；禁止所有地面metallic=1 |
| murk 荧沼 | 泥岸、浅水、局部腐殖 | 芦苇、根拱、荧光菌和浮叶 | 低雾/湿润、桩屋栈道；夜光点小而有层次，不用全屏绿色 |
| salt 盐滩 | 干裂盐壳、卤水池、层状边缘 | 稀疏盐晶、漂木 | 高反差天空、轻雾、平台式废墟；盐白与雪白材质不同 |

| hive 蜂窝 | 六边穹丘、孔洞、壳层 | 膜翼草、孔缘碎壳 | 浮尘/独特高云、蜂窝遗迹；重复六边形要有尺度破缺，可达路线清楚 |

每生态建立至少一个可游玩美术样本区和一条飞行远景路线。新增素材族可以共享材质/网格，但每生态至少有一个独特地貌轮廓、一个植被/道具轮廓和一个天气/光照特征。不能把16个色相变体计为16生态完成。

## 3.5 植被、碎石与地表动态

### 分布与生成

1. 地形生成阶段输出坡度/湿度/海拔/遮蔽/地表类别摘要；装饰生成读取摘要，不反复射线遍历所有方块。
2. 用簇状层级采样：先大簇，再小簇，再稀疏散点；密度由生态和地貌mask控制。Poisson等最小距离规则按稳定cell哈希实现，跨chunk边界一致。
3. 已有可砍树木保留逻辑树/方块；树叶小枝、草簇、石屑是视觉附属，关联支持块和revision。砍树/挖底块自动移除附属物。
4. 为道路、门、机器维护口、飞船降落区、出生点生成排除mask；主路径留视线走廊。
5. 从风采样驱动草/叶/树枝不同频率，根部权重=0，顶端有限位移；相同风用于雨/尘/烟，避免风向矛盾。
6. 批处理/实例化优先，按材质和mesh分桶；每根草独立Entity只在有明确交互需求时采用。

### LOD与遮挡

1. 近景有体积的叶簇，中景简化卡片，远景颜色/法线impostor；转换保持树冠体积和颜色。
2. 风动影响bounds，包围盒加入最大位移；否则树叶在视锥边缘闪灭。阴影pass与主pass同风动。
3. cutout植物先解决mip coverage，再评估temporal dither；透明Blend只用于确有透明需求的膜/孢子，避免森林透明排序爆炸。
4. 近景草与第一人称镜头保持舒适距离；不要将草片裁剪弹出误当“自然淡入”。

### 湿润、积雪、积灰、脚印

1. 天气驱动宏观wetness/snow/ash状态，局部遮雨mask避免室内下雨湿地；积雪厚度先做视觉，不增加隐形碰撞。
2. 湿润改变albedo/roughness和小水洼mask，不能所有表面镜面化；垂直墙与水平地面不同响应。
3. 脚印/车辙/弹痕有限数量、距离和寿命，附带基面revision；基面被挖后移除，不能悬空。
4. 模拟时钟与表现时钟分开，暂停不无限累积雨事件；快进天气要限速过渡。
5. 环境碎屑无库存价值，若需变成可采对象必须显式接入掉落与联网，不按画质偷偷生资源。

## 3.6 程序化建筑：目标产出

以当前5×5小屋和3类遗迹为兼容基线，新增一条可解释、确定性、有验证器的建筑生产线：

`候选区域 → 场地采样 → 聚落骨架 → 道路/地块 → 建筑体块 → 房间/门窗/楼梯 → 地基与屋顶 → 家具与功能锚点 → 磨损/植被 → 逻辑验证 → 预算检查 → 分区块落地`。

首轮内容目标：6类聚落用途（拓荒居住、矿业、农业/生态、研究、物流补给、海岸/沼泽桩基），每类3种以上经过人工审稿的布局骨架；12类建筑用途（小屋、长屋、宿舍、工坊、仓库、市场、医疗、科研、供能、温室、瞭望塔、登陆服务）；6类遗迹（环柱、塔、庭院、坍塌工厂、地下入口、蜂窝遗构）。生态调色/材质变体不计独立功能原型。

模块初始库约80–120件：墙/转角/门/窗/基座/地板/顶/脊/檐/楼梯/栏杆/桥/支柱/管线/家具/标识，按具体审稿需求增长。先完成一个主题的完整模块库，再扩张风格，不先做一百件无组合测试的碎件。

## 3.7 G01 · 稳定种子、版本与查询边界

1. 定义stable structure id：由world/planet/generator_version/region coordinate/local index派生；细分随机流为选址、布局、屋顶、家具、损毁、装饰、奖励。
2. 增加装饰时只消耗装饰随机流，不让房子改位置、宝箱换物品。整数哈希与排序规则有黄金样本，避免HashMap遍历影响结果。
3. `StructurePlan`先生成完整宏观方案，再按chunk裁剪写入；不能一个chunk随机决定门，另一个决定楼梯。
4. 当前±1结构格查询为约20格旧结构半径设计；新聚落更大，查询范围必须由真实AABB/索引计算。不得保留旧注释然后造百米聚落导致截断。
5. 每计划限制最大边界、模块数、体素写入数、递归深度、候选次数、耗时；超限返回诊断并选安全小模板。
6. 缓存按稳定ID和版本，有容量/淘汰；对无限世界禁止永久缓存所有探索过的程序化计划且永不清理。

## 3.8 G02 · 选址、街道与地块

1. 区域候选采样高度、坡度、水位、可建面积、洞穴/悬空风险、到出生点距离、生态限制。中心一格在陆地不代表整房在陆地。
2. 用整个footprint及周边安全带计算地形误差；给平地/坡地/桩基/崖边不同评分和工程限额，过陡拒绝或小规模台地化。
3. 先确定中心地标、入口、主街、次路和公共空间，所有房门朝向可达道路；保留视觉通廊和从远处识别的剪影。
4. 地块有占用AABB、退线、门前空间、维修区、桥/楼梯接口；邻近结构跨region冲突按稳定优先级裁决，避免两边都觉得空地。
5. 道路规划代价考虑坡度、水、房体、资源重要点；用有限搜索预算、最大坡度和路宽约束。失败先减地块/改入口再落安全布局。
6. 人行道路包含转角、台阶、桥、栏杆、灯、路面材质过渡；装饰避让道路mask，路面跟地形相接，不能贴片悬空。
7. 保持无危险生态原点附近可用村庄这一现有任务依赖。若新选址失败，使用确定性安全地基/旧模板fallback，不能生成空图还让任务指向不存在村庄。

验收：在平地、坡地、海岸、跨chunk角、负坐标各生成；从聚落外到中心、每间建筑入口及任务NPC均可到达。邻格竞争按不同加载顺序生成同布局。

## 3.9 G03 · 建筑体块、模块和地基

### 白盒到成品的步骤

1. 用功能图规定房间关系，例如住宅入口→起居→睡眠/储物；工坊入口→工作区→仓储→维修口。先做可进入白盒，不贴材质。
2. 根据地块尺寸选择矩形/L形/院落/分体/塔楼体块，在规则中标注入口、层高、楼板、承重逻辑和屋顶排水方向。
3. 由实际Player collider推导门宽/高和楼梯净空，预留安全余量；两格门只是旧实现，不强制所有新门都适用。楼梯踏面/坡度和玩家步高验证一致。
4. 模块具有socket类型、方向、尺寸、允许邻接、支撑/开口标签；连接失败不能强行挤压缩放门框。
5. 地基按采样选择台阶基础、短支柱、桩基、嵌岩或有限挡土墙；填挖量有上限，长柱底端必须落到有效支撑，不吊在洞顶空气里。
6. 楼板闭合、墙角无漏缝、屋檐有厚度、坡顶有屋脊和收边、门窗与主体材料比例一致。不要用随机删块制造“风格”。
7. 玻璃、栏杆、檐口等装饰不重复绘制已有体素面；如视觉替代一面，定义可见面抑制规则并保留逻辑命中。
8. 结构中不同材质只由风格模板选择，同一建筑不随机用五种不相关墙材。建筑年龄/用途影响磨损和附属物，而不是随机平均铺满。

### 可破坏性策略

主体用逻辑体素；非格装饰附着在稳定结构/支持块上。支持块被拆，相关装饰移除或切破损变体；不默认启用真实结构坍塌物理。玩家修改优先于生成器。若门/楼梯改为逻辑实体，明确其碰撞、状态、保存、联网和资源退款；不能只在GPU模型里留门洞而物理仍是实心墙。

验收：从外部进入各房间、上下楼、沿檐观察、拆角柱、拆门、挖地基、读档恢复；不存在不可见碰撞、重复墙、悬空家具或穿顶楼梯。

## 3.10 G04 · 室内、功能、灯光和生活痕迹

1. 家具用用途集合布置：睡眠床柜、工坊工作台工具、仓储货架托盘、医疗床屏幕、研究仪器、市场柜台；每件有footprint、朝向、交互面和靠墙偏好。
2. 为门扇、过道、楼梯、服务柜台、NPC站位保留净空；从入口到所有交互点做导航连通性验证。
3. 生活痕迹分密度层：主体家具、少量使用中道具、局部污渍/磨损。每房随机种子独立，不能每张桌子都同一摆法，也不能塞满垃圾。
4. 所有可交互容器/终端映射现有玩法或显式新逻辑。纯装饰箱不显示可打开提示；可开箱生成stable ID并保持领取状态，重载不能刷物资。
5. 室内光源有安装点和供电/用途解释，直接灯和发光材质成对。封闭房间遮雨，窗边光、门外光、局部灯有层次；必要遮挡数据向D提供。
6. NPC岗位、交谈点、巡游路径与任务锚点来自结构计划；站位不靠“中心加随机偏移”，防止在屋顶/墙内/水下。
7. 标牌采用统一UI图形语言并考虑中英文；世界标牌文字LOD在远处转简洁符号，不超量动态字体纹理。

验收：每种用途至少一个完整房间，夜晚/停电/雨天可走可交互；空闲和拥挤NPC场景无堵门；外观不向玩家承诺未实现功能。

## 3.11 G05 · 遗迹、磨损与环境融合

1. 从完整结构模板生成损毁，记录原有支撑和主要构图，再按损毁中心/风蚀方向/侵蚀高度作用；不独立随机删除每块。
2. 保留主地标、入口、奖励路线和战斗空间。倒塌梁、残墙、瓦砾使用有限模板与支撑检查。
3. 将碎块布置在坍塌方向和地面低点，避开主通道、战利品和守卫spawn点；decor budget不足先删小碎片，不删识别地标。
4. 苔藓/灰尘/盐霜/沙埋受生态、朝向、湿度/遮挡影响；接触处有材质过渡，地基周围不留规则切割矩形。
5. 守卫路径、攻击空间、玩家掩体和退路需实测。视觉遮挡与实际弹道碰撞一致，不让玩家被看不见的守卫隔墙射击。
6. 保存清理/采集/击杀状态；重生规则沿用玩法，不因美术装饰换版本而刷新守卫和宝箱。

## 3.12 G06 · 旧存档迁移与联机

推荐默认策略：**旧世界维持旧生成器，允许新的纯视觉皮肤；新世界使用新生成器**。这能保留探索过与未探索过区域的一致基础，先把功能交付。若要求同一旧世界接入新建筑，必须另做按区域生成版本和保护边界，不能只对“当前加载chunk”保留旧版。

迁移步骤：

1. 备份旧档到隔离目录，读取SAVE_VERSION=5样本，记录方块修改、机器、任务NPC/结构锚点、地图标记、星球/星系归属。
2. 缺generator_version的旧档明确映射legacy版本；保存新字段时不重新生成整个世界。旧生成代码保留到迁移保证完整。
3. 如采用区域升级，冻结旧探索/修改区域与缓冲带；新区域边界有道路和地貌过渡，旧地块不因新选址冲突被覆盖。
4. 美术装饰规则随visual version可变化，但逻辑房体、奖励与NPC任务ID不变；附属物破坏掩码有上限和压缩策略。
5. 主机提供生成版本/模块规则hash，客户端校验；只同步可重建的逻辑计划或必要增量，不传大量纯视觉叶片/家具粒子。
6. 客户端不同画质看同一门、楼梯、箱子和掩体；缺美术包用同碰撞/交互的fallback，不改变路径通行。
7. 在跨星球/星系存档及迟加入回放中确认plan和delta归属；老world_epoch返回任务不能生成在新星球。
8. 新版本无法读取更高版本生成规则时给清楚诊断，禁止静默以旧算法重新生成玩家基地。

## 3.13 自动验证器与质量采样

为每个StructurePlan输出：候选评分、拒绝原因、布局图、地块边界、道路graph、房间graph、支撑、净空、交互点、体素修改摘要、LOD代理、资源预算和稳定hash。

验证层次：

- 纯数据：有限值/范围/ID唯一/无循环非法引用/边界覆盖/随机流确定性。
- 几何：地基接地、模块无非预期穿插、门窗对齐、屋顶闭合、净空足够、不会超WORLD_H。
- 玩法：出生到地标/入口/NPC/奖励可达；不能覆盖玩家修改；资源/容器不重复。
- 性能：生成耗时、模块/材质/灯数、mesh大小、任务队列峰值有限。
- 艺术：轮廓变化、道路构图、材质协调、细节密度、室内用途可读，由人工判，不用通过率替代审美。

M2每类结构至少50个种子人工联系表抽检；M3全体做1,000个快速数据样本和至少100个几何/导航样本；发布前扩至10,000个数据样本、选最差评分和边界样本人工游玩。先测验证器能否抓住故意注入的悬空、堵门、截断、重复ID；通过率必须包含被拒绝候选/fallback比例，不能删坏seed再报告100%。

失败处理按“重选地块→简化体块→减少附属→安全模板→明确报告”，有最多重试次数。输出失败seed和版本以便修复；不在玩家加载线程无限重试。
