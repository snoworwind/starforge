# 05 · 66个工作包、依赖、预算与交接

本文是执行索引；各包必须连同00–04详案和06验收/风险阅读。所有条目初始状态都是 `planned`，尚未分配负责人。表中Rust预算为净增物理行的规划分配，不是最少提交量；不鼓励填充。依赖是必须先稳定的接口或能力，不要求等待依赖流全部完成。

## 5.1 所有工作包共用完成定义

每包都必须交付：①可运行集成而非孤立演示；②数据/配置及有效默认值；③对应资产或明确不需要资产的理由；④关键异常/边界测试；⑤固定场景前后图/视频或纯数据报告；⑥CPU/GPU/内存影响；⑦fallback/回滚说明；⑧更新本包状态和限制。纯架构包没有视觉变化时提交行为等价与生命周期证据，不伪造前后效果。

一个PR建议只含一个可审变化；较大包拆为“适配/纯算法→视觉接入→资产覆盖→回归”子PR。正常单PR尽量控制在500–1,500行有效变化，生成清单和测试数据另列；不是机械禁止较大改动，但上千行算法、艺术资产和全局重排不能揉成不可审的一次提交。

状态登记拟放 `docs/art-overhaul/progress/<ID>.md`（认领时才创建），包含负责人、开始基线、PR/提交、状态、证据路径、剩余项。不要直接把规划详案大段删成“已完成”。

## 5.13 后续多agent协作及接口冻结

可以按A/D/E渲染、B美术技术、C/F环境、G建筑、H/I表现、J界面分工；实际并行度以工具/人员条件为准。公共文件由集成负责人单点合并。不要让两个agent同时改同一个材质布局或shader binding。

三个冻结点：M0冻结VisualFrame/SurfaceMaterialId/StructurePlan最小字段；M1冻结mesh属性、shader binding和相机合成依赖；M2冻结generator/material/asset版本及核心UI事件。冻结后变更需要ADR：原因、受影响工作包、迁移、回滚、验证，不能偷偷换字段含义。

如果前置包阻塞，继续不依赖它的资产制作/纯算法验证；不能写“临时”重复体系规避依赖。超过预算20%时先说明新增问题和质量收益，再重排范围，不能为了守行数砍兼容/QA。
