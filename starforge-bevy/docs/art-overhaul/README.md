## 1. 目标与阅读方式

把目前“功能较齐全、视觉表现仍明显原型化”的 Bevy 版，提升为风格一致、近景精细、远景稳定、天空可信、建筑有设计感、交互清楚的风格化体素星际工厂游戏。保留可挖掘、可建造、可跨星球飞行和自动化生产的身份，不能以关闭玩法、缩小世界或只改善摄影模式来换取截图效果。

预计净增约 **50,000 行自有 Rust 源文件物理行**，目标区间 40,000–60,000；包含正常注释、格式化和必要测试，不能用空行、自动生成常量、重复模板或复制第三方源码凑数。运行时、工具与测试分别记账，搬移旧代码不算增长，删除旧实现必须从新增中扣除。美术资产、WGSL、配置和文档单独统计。质量目标是硬门槛，行数只是工程容量预测。

## 2. 风格方向与成功定义

默认采用“**精致体素轮廓 + 风格化 PBR + 克制的科幻信息设计**”。地面方块仍清晰可数；金属、岩石、木材、玻璃、冰、水可以凭反射和表面结构区分；机器和建筑有中尺度体块和小尺度构造；异星生态以形态、天气和空间构图区分，而非仅换颜色。传统像素模式保留为独立艺术预设。

以下七项全部满足才算完成：

1. **一致性**：同一灰球和色卡场景中，地形、机器、外部 glTF、角色、道具曝光与材质一致；外购模型经过统一加工，不形成素材拼盘。
2. **可读性**：地表矿物、交互目标、机器运行状态、敌我关系在白天/夜晚/恶劣天气都可辨认。UI 在 1280×720 和 200% 缩放下主要流程完整可操作。
3. **细节层次**：每类关键对象具有远处轮廓、中距离构造、近处材质三个层次；不以统一高频噪声覆盖所有表面。
4. **连续性**：步行、冲刺、飞行、穿云、再入和跃迁后返回时没有明显地形洞、云层跳变、错误阴影、重复建筑或相机抖动。
5. **程序化可信度**：道路连门、地基接地、室内可进入、屋顶闭合、功能空间合理、损毁有结构逻辑；同一种子不因加载顺序或画质改变建筑和战利品。
6. **可交付性**：冷启动、缺少外部大素材、离线安装、存档升级、联机迟加入、最小化恢复均有明确路径；美术更换不能毁坏旧世界。
7. **性能与维护**：固定场景达到经测量确认的预算；所有新增 GPU 通道有诊断和降级；模块有负责人、配置、测试与移除旧路径的条件。

视觉评分采用 1–5 分锚点：1=影响游玩/明显错误，2=原型，3=功能清楚但重复感明显，4=发布质量且整段运动稳定，5=有辨识度且细节、构图、技术稳定性均突出。评审维度为材质/光照/天空/地形连续性/建筑/生态/角色机器/UI/运动稳定性；最终各项至少 4，且不得有阻断缺陷。评分须由至少两名评审对同种子、同曝光、同机位的前后图与视频进行，不能用单一美图平均掩盖差场景。

## 3. 工程预算

| 流 | 范围 | Rust 净增预算 | 首要交付 |
| --- | --- | ---: | --- |
| A | 基础架构、视觉快照、画质、生命周期 | 4,000 | 可重复基准场景、单一视觉接口 |
| B | 资产导入、材质库、纹理管线、图标 | 4,500 | 完整材料样板和资产检查器 |
| C | 地形网格、LOD、异步流式、修改传播 | 6,000 | 无裂缝、无闪变的地面至轨道过渡 |
| D | 光照、阴影、大气、曝光、后处理 | 4,500 | 白天/夜晚/室内/太空统一照明 |
| E | 云密度、光照、重建、云影、跨尺度 | 5,000 | 可穿越且时间稳定的天气云系统 |
| F | 生态、植被、水体、地表动态、环境 VFX | 4,500 | 16 生态完整表现 |
| G | 建筑语法、布局、道路、地基、室内、遗迹 | 8,500 | 可验证的聚落与遗迹生成系统 |
| H | 机器模型、物流表现、连接件、状态效果 | 3,500 | 全机器视觉族与正确状态反馈 |
| I | 角色、生物、飞船、空间站、交互 VFX | 3,000 | 统一外观和动画资产契约 |
| J | UI 设计系统、所有界面、可访问性、摄影 | 5,000 | 全流程一致的产品 UI |
| K | 集成验证、性能回归、打包、交付 | 1,500 | 可复现验收和发布记录 |
| **合计** | 含各模块自测，K 只计跨系统工具 | **50,000** | 质量达标后允许少于预测 |

建议约 8,000 行分散用于算法/状态/回归测试，其余约 42,000 行为运行时和生产工具；不设强制占比。WGSL 预计另需数千行，资产工作量远大于其代码行数。材质绘制、模块建模、蒙皮、动作、图标和人工视觉评审都必须单独安排；不能假定“写完 Rust = 美术完成”。

排期以 A/B/C/D/E/G 六个原型验证后的真实速率修订。初步容量规划为工程 80–140 人周、美术/技术美术 40–80 人周、专门 QA/集成 20–40 人周，总 140–260 人周；角色可重叠但工作量不能重复扣除。按 5 名有效全职投入粗算约 7–12 个月，考虑依赖与集成后预留到 8–14 个月。此为规划假设，不是已评估团队的承诺；每阶段输出剩余工作和风险重估。

源文件拆分先保行为，再实现效果；默认采用 `codex/` 分支前缀。后续若安排多个 agent，可以按流分工，公共类型和 `main.rs`、`schedule.rs`、`save.rs`、`data.rs`、`Cargo.toml` 由集成负责人串行合并。本文是后续执行规则，不表示本次已经创建并行 agent 或分支。
