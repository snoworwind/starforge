## 交付契约

1. `WorldEpoch` 只有一个推进入口 `advance_world_epoch`：
   - `OnEnter(Loading)`：新世界和读档在构建前推进；
   - `planet_switch_system`：活动体素星球替换前推进；
   - `OnExit(Playing)`：返回菜单时推进。
2. `VisualLifecycle` 统一持有：最后一次 transition、相机尺寸/暂停状态、history reset 原因、有限异步任务登记。
3. `VisualTaskRegistry` 默认容量 256。任务输入/结果都带 `id + owner + world_epoch + revision`；主线程提交前校验。队列满、取消、旧 epoch、旧 revision 和未知/重复结果分别计数，不允许旧 CPU 结果创建/替换 Bevy asset。
4. `VISUAL_OWNERSHIP` 冻结首批真实拥有者：应用常驻 UI 图标/粒子共享资产；星球级地形材质、气候和 LOD；区块 mesh；相机 history；天气与游戏实体。每项带释放边界。
5. `VisualLifecycleDiagnostics` 每帧输出 epoch、transition、history、任务队列、9 个拥有者的实体/强句柄/排队数，以及全局 Mesh/Image/StandardMaterial/CurvedMaterial/CloudMaterial 资产计数。它们是资源计数，不冒充 GPU 显存实测。

## 实际接入与修复

- `sample_visual_frame` 在最终相机采样点观察真实 viewport。新相机、epoch 变化、resize、零尺寸窗口和恢复都会记录 reset；reset 帧令 `prev_view(_proj) == current`，不会把旧世界/旧尺寸矩阵送给后续重投影。最小化时保留最后一个有效尺寸并标记 `camera_suspended`，后续 RT 所有者可据此暂停分配。
- `ClimateRuntime.fingerprint` 加入 epoch。同 seed/同 biome 的另一颗星球不再复用云 elapsed、density 或 material。星球切换发生在普通气候系统之后，因此增加同帧失效系统：立即销毁旧云/降水/雨声并释放强句柄，下一帧才为新星球重建。
- `LodRuntime` 从 `world_seed` 改为 `world_epoch`。进入新 epoch 时移除 resident mesh；返回菜单的 `OnExit` 显式释放 mesh asset 和已失效 Entity 记录，避免菜单中继续强持有以及再次进入相同 seed 时复用死 Entity。
- legacy `FarMesh` 同时记录目标 epoch 和 active mesh epoch。同 seed 星球切换仍会重建；staging 未完成时旧星球 active mesh 保持隐藏，完成后才原子交换显示。
- `quit_to_menu_system` 不再自行 remove/reinsert `ClimateRuntime` 或手工清空 `RainAudio`；天气插件成为这些资源的单一释放所有者。
- A01 `metrics.json` 增加完整 `visual_lifecycle` 快照，后续循环切换、S21/S24 和 K03 可直接比较，不需要解析每帧日志。

3. 真实最小化/恢复和 DPI 事件未由 OS 注入；camera lifetime 状态机有单测，S24 仍需目标平台运行。
4. diagnostics 的全局 asset 数是 Bevy `Assets` 条目数，强句柄数只统计登记缓存；不是驱动显存、RSS 或隐藏 render-world 资源。K03 必须另测。
