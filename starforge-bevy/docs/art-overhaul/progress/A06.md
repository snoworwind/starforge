## 交付内容

1. `src/app.rs`（新）：单一应用装配入口
   - `main()` 变为两行薄入口；`StarForgePlugins`、`GameFlowPlugin`、启动相机 `startup`、可执行文件旁素材装配全部集中到 `app::run()`，插件注册顺序与拆分前逐项一致（A01–A05 无行为变化）。
   - `LaunchOptions::parse(args)`：一次性解析 `--smoke/--play/--clouds-off/--climate-on/--legacy-lod/--simulate-low-device/--lod-log/--visual-qa*`；纯函数便于单测。
   - `add_plugin_once<P>()`：重复注册改为 warn + no-op（Bevy 对 unique 插件重复添加会 panic），覆盖 `EguiPlugin`/`GameFlowPlugin`/`VisualQaPlugin`；`StarForgePlugins` 组内仍由 Bevy 自身去重语义保护。
2. 最小/完整素材路径接入
   - `AssetBootstrapReport` 区分仓库自带 `REQUIRED_ASSET_FILES`（模型/着色器；音频与字体为 `include_bytes!` 编译内嵌，不需要运行时素材）与下载包 `OPTIONAL_ASSET_FILES`（外部飞船/空间站/地球，10 项）。
   - `resolve_asset_root`：默认 `exe/assets`；`STARFORGE_ASSET_DIR` 测试钩子可指向隔离目录（K04 冷安装用）；启动打印 `full/minimal asset mode` 与缺失清单。
   - `bootstrap_assets`：仅当对应顶层组缺文件时才从源码树复制，避免缺一个 shader 就重拷数百 MB 模型；这是对原启动自解压逻辑的收敛。
3. 旧入口收敛
   - `lod.rs`：删除 `hierarchical_lod_system` 内的 `static OnceLock + std::env::args()` 首次帧扫描，改为 `LodLogging` 资源（`app` 统一解析后注入，`LodPlugin` `init_resource` 兜底），`--lod-log` 行为不变。
   - `ui.rs`：`UiPlugin` 断言 `EguiPlugin` 已注册，保证单一 egui manual pass 的所有权（“UI 多 pass”防护）。
   - `main.rs`：2125 → 1677 物理行；不再有第二处 `std::env::args()`、第二处 `AssetPlugin` 路径推导或启动期文件复制。
4. README 真实功能修订
   - 新增“视觉 QA 与诊断工具（真实 CLI）”表：`--visual-qa*`、`--climate-on`、`--clouds-off`、`--legacy-lod`、`--simulate-low-device`、`--lod-log`、`STARFORGE_ASSET_DIR`、最小/完整素材路径说明。
   - 修正过期描述：250 格曲率 → `planet_scale` 半径 16384 / 平坦 256 / 全曲率 1500 + `planet_curvature*.wgsl`；删除不存在的 `vendor/bevy-volumetric-clouds` 署名，改为自研 `cloud_shell.wgsl` + `CloudShellMaterial`；目录结构加入 `app.rs`/`visual/`/`visual_qa/`，着色器清单改为实际 3 个文件。
