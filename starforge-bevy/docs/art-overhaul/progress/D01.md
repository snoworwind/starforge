## 交付内容

1. `src/rendering/inventory.rs`：`PassInventory`（PostStartup 采集一次并导出 `<run>-rendering.json`）
   - 逐相机记录实际情况：kind（primary_3d/overlay_2d）、order、Hdr、Msaa、Tonemapping、Exposure.ev100、
     clear、DepthPrepass、Bloom（强度/阈值/软度/低频）、SSAO、ContactShadows 长度、大气方式与
     environment fill、DistanceFog、RenderTarget 类型与尺寸（window / image + 真实 `TextureFormat`）、
     采集时 viewport，以及 shadow map 与全局 ClearColor。
   - 11 个 pass 的声明式顺序（depth prepass → shadow → main opaque → sky/atmosphere → cloud shell →
     transparent → bloom → D01 probe → tonemapping → upscaling → egui UI），每个含 schedule、输入、输出与
     fallback 说明；插入点来自锁定 0.19.1 源码（`FullscreenMaterialPlugin` 默认
     `Core3dSystems::PostProcess` + `before(tonemapping)`）并由抓图证实，不使用网页未验证接口。
   - 6 段颜色链（sRGB albedo → 线性材质 → 场景线性 HDR → probe → ACES 一次 → 呈现），以及 AA 能力矩阵：
     当前 `Msaa::Off`、`rgba16float MULTISAMPLE_X4` 支持、DepthPrepass 生效、motion vectors 未接线、
     FXAA/SMAA/TAA 编译可用但未选择（选择权归 D06）。
2. `src/rendering/probe.rs` + `assets/shaders/visual/exposure_probe.wgsl`：最小 HDR 全屏后处理原型
   - 使用锁定版本的 `FullscreenMaterial`（`ExtractComponent` + `UniformComponentPlugin`），在 tonemapping
     之前读写场景线性 HDR view target；三种真实模式：false-color EV 分带、裁剪 zebra、log 亮度。
   - `--render-probe off|false-color|zebra|luminance`（只读，不写 settings/save）；`ProbeStatus` 记录
     requested / shader_loaded / shader_failed / active / cameras / **activations / active_frames** / reason，
     避免“开关无效也显示已生效”（R117）。
   - 失败路径（R011）：shader LoadFailed 只处理一次并自动关闭请求；无组件时 pass 不执行，场景走原路径。
     不支持 HDR/filterable 目标时拒绝激活并写明原因（R012/R045）。
3. `src/rendering/mod.rs`：`LightingProbe`（Full/SunOnly/AmbientOnly，默认 Full）由 `daynight_system` 消费，
   仅缩放太阳/环境/环境图补光三个通道，不改 `Settings`。
4. `visual_qa` D01 场景与通道矩阵
   - `SceneId::D01`：7 张精确 scene-linear PBR 灰卡（黑 0.03 / 18% / 50% / 90% 白 / 过亮自发光 / 金属 /
     饱和色）+ 带门、窗、室内灯与室内灰卡的封闭房；10 个固定机位。
   - 变体：`full`、`no_post`（移除 Bloom/SSAO/ContactShadows）、`sun_only`、`ambient_only`、
     `probe_stops`（false-color）、`probe_zebra`；`cards_*` 6 张、`room_*` 3 张、`room_inside_full` 1 张，
     文件名即变体名。进入 D01 时保存原始后处理组件，Drain 时恢复，保证同轮后续场景不受影响。
   - `ProbeCards` 走真实 `Assets<StandardMaterial>` 管线；`MANIFEST_SCHEMA_VERSION` 2→3 仅为附加的
     `scene.poses[].variant` 可选字段。
5. 接入与登记：`main.rs` 的 `mod rendering`、`app.rs` 的 `RenderingPlugin` 与 `--render-probe`、新 shader 进入
   `REQUIRED_ASSET_FILES` 与 B01 `art/manifest.rs`（`shader.exposure_probe`）、README CLI 表与报告说明。

## 兼容、回滚与故障注入

- 存档/网络/依赖：零变化；`Settings`、`SAVE_VERSION`、协议、`Cargo.toml`/锁文件未改；probe 与
  LightingProbe 只在运行时存在，默认 Off/Full，不落盘。
- 调度：`RenderingPlugin` 在 `VisualPlugin` 之后注册；inventory 在 `PostStartup` 采集（相机已生成、
  能力资源已插入）；probe 同步系统在 `GameSet::CameraFx`（相机写入之后、渲染提取之前），同帧生效。
- 回滚：删除 `src/rendering/`、`main.rs` 的 `mod rendering`、`StarForgePlugins` 中的一行、`daynight.rs` 的
  `probe` 参数、`visual_qa` 的 D01 场景/变体/write_rendering_report、`--render-probe` 接入、新 shader 与
  manifest 条目即可；D01 场景为 opt-in，默认 A01 场景集与输出不受影响。
- 已注入/已覆盖：非法 `--render-probe` 值 warn 后忽略；probe 模式非法值不 panic；uniform NaN/∞/越界回退；
  shader LoadFailed 处理器存在（单测覆盖分类，未做真实坏 shader 设备注入）；D01 变体切换后的恢复由
  S01→D01→S02 链验证；低设备仿真不黑屏。
- 未注入：真实非 HDR/filterable 设备上的 probe 拒绝路径只有逻辑与单测，无该硬件或强制特性注入。

   与两种 probe。阴影级联、bias、曲率 prepass 一致同为 D03。
3. 像素模式（Camera2d overlay + 640×360 Rgba16Float Image target）与 photo 相机未被 QA 运行实际采集：
   `--visual-qa` 在内存中强制 `pixelated=false`；inventory 查询覆盖这些相机，但需要 J06/S20/S24 另跑。
4. 天空/云与地表“同一曝光尺度”目前由 probe 叠加可视化提供，没有 CPU 数值回读；E01/E03 需按 02 的
   云矩阵给数值与 history 重置原因。
5. AA 路径只建立矩阵，FXAA/SMAA/TAA 的选择与 motion vector/depth prepass 组合归 D06；动态分辨率未做。
6. D01 抓图仍含实时玩法元素与 HUD（A01 已记录）；没有“冻结玩法”开关。
7. 未在 Linux/打包发布目录运行断言（逻辑与路径无关，但无该平台证据）。
