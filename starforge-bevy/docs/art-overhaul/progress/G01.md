## 交付内容

1. `src/structures/`（00.3 规划的 structures 落点）：
   - `plan.rs`：`LegacyLayout`（冻结的 v1 村庄/遗迹数据）、`StructureId`（world_seed + generator_version + cell + local_index + kind）与 `stable_hash`；`StructureStream`/`StreamSeeds`（site/layout/roof/furniture/damage/decor/loot/terrain 八条流，由稳定 id 派生，不依赖调用顺序）；`PlanAabb`（真实 footprint）、`PlanModule`/`PlanAnchor`、`PlanStats`/`PlanLimits`/`LEGACY_LIMITS`、`PlanIssue` 与 `validate`；`layout_fingerprint`/`loot_fingerprint`/`plan_fingerprint` 规范 hash；`plan_search_margin` 版本表。
   - `query.rs`：`cell_range_for_rect`（矩形 + 版本化 margin，`div_euclid` 覆盖负坐标/饱和边界）、`PlanCache`（有界 FIFO、Mutex 内部化、命中/未命中/淘汰统计、空格也缓存）与 `PlanCacheStats`。
2. `rng.rs`：拆出 `hash2_state`（`hash2` 行为不变），让 plan 的 `layout` 流与旧 `hash2(ccx, ccz, 0x57A7C7, seed)` 序列逐位一致。
3. `world.rs` 接入（`stamp_structure` 一字未改）：
   - `WorldGen` 缓存由无界 `Mutex<HashMap<..>>` 换成 `PlanCache`（默认容量 4096）；
   - 新增 `plan_in_cell`（返回 `Arc<StructurePlan>`）与 `plan_cache_stats`；`structure_in_cell` 保留为冻结布局兼容入口；`structures_in_rect` 用真实 AABB 过滤，不再依赖「±1 格覆盖一切」；
   - `Structure` 变为 `structures::LegacyLayout` 的兼容别名，quests/creatures/ui 等消费者零改动。
4. 证据出口：`visual_qa` 的 `metrics.json` 增加 `plan_cache`（命中/未命中/淘汰/容量），并注明淘汰只重建相同计划；README 增补 `structures/` 与计划缓存说明。

## 兼容、回滚与故障注入

- 存档/网络/依赖：零变化。计划不序列化、不进存档；旧档仍按同一种子重建同样布局（18 个 chunk 指纹是硬证据）。`SAVE_VERSION`、协议、`Cargo.toml`/锁文件未动。
- 消费者：`world::Structure` 变别名后 quests/creatures/ui 编译与行为不变（它们仍对中心点做距离过滤；AABB 预过滤只会剔除本来就在查询矩形外的结构）。
- 回滚：删除 `src/structures/`、恢复 `world.rs` 原 enum/无界缓存/`structures_in_rect`、去掉 `rng::hash2_state` 与 `metrics.plan_cache` 即可；golden hash 会守住任何顺手改动。
- 已注入/已覆盖：反向矩形、负坐标、`i32::MIN/MAX` 饱和、远区块、危险生态原点（ruin/无）、空格缓存、容量淘汰、八流隔离、超预算计划拒绝。
- 未注入：真实大型聚落（v2）尚未存在，margin 表的扩展路径只有单测级约束；缓存未做并发压力（WorldGen 目前主线程消费）。

## 未完成 / 未验证

1. v1 仍是「每格最多一个计划」，`local_index` 已被 id/流支持但未使用；多结构/大地块是 G02。
2. `GENERATOR_SEARCH_MARGINS` 目前只有 v1 一行；G02+ 引入更大 footprint 时必须加行并补「宽域扫描无漏」回归，不能沿用旧 ±1 假设。
3. `PlanCache` 是 FIFO 而非严格 LRU，容量固定 4096、不可配置；淘汰代价与命中率需 K03 用长路线实测再调。
4. `structures_in_rect` 仍返回克隆布局，`stamp_structure` 未改为消费 `PlanModule`；G03/G05 接入体块/装饰时再做，并以本次 golden chunk 指纹作为对照。
5. `PlanAnchor` 目前只含旧实现的 beacon/lamp，还不是 NPC/任务/宝箱锚点（G04）。
6. 本包是纯数据/算法改动，没有新增截图；证据是黄金 hash、宽域扫描单测与 QA `plan_cache` 计数。未在 Linux 运行。
